# Data dictionary: mobile-game player spending segments

## Dataset identity

| Item | Description |
|---|---|
| Source file | `data/01_original_kaggle_data.csv` |
| Source dataset | [Mobile Game In-App Purchases Dataset 2025 on Kaggle](https://www.kaggle.com/datasets/pratyushpuri/mobile-game-in-app-purchases-dataset-2025) |
| Original source dimensions | 3,024 rows × 13 columns |
| Expanded cleaning file | `data/02_expanded_dirty_data.zip` |
| Expanded dimensions | 250,000 rows × 23 columns |
| Target | `SpendingSegment` |
| Important provenance note | The publisher describes the original source as synthetic. The expanded file is generated by resampling and perturbing source records; it is not a collection of 250,000 independently observed players. |

The expanded file is intended to demonstrate data cleaning at scale. Check the course's approval requirements before treating it as an accepted substitute for the minimum real-data requirement. See the README and `docs/report_completion_checklist.md` for the project's limitations and evidence checks.

## Cleaning rules implemented in `src/clean_data.py`

The cleaning script first removes exact duplicate rows and trims text whitespace. It maps a small set of known category variants, converts explicit seconds values to minutes, removes currency symbols before numeric parsing, and checks numeric fields against documented ranges. Invalid values are set to missing rather than silently changed to positive values. Date fields are parsed, future install dates and reversed install/purchase order are flagged, and remaining missing values receive simple median, mode, or median-timestamp imputation for the descriptive cleaning export.

The cleaned export is intended for descriptive analysis. The model script uses a separate preprocessing pipeline fitted only on training data. It does not use the expanded cleaning output for model evaluation. Run `python src/clean_data.py` to create `outputs/data_quality/cleaning_audit.json`; use that generated audit for the actual issue counts and before/after results.

## Known limitations

The original source is small and described as synthetic by its publisher. The expanded data inherit this synthetic basis and add further generated records and fields. Target classes are related to spending amount, and the source does not provide a validated time-based forecast design. In addition, generated rows may share patterns with source records. Therefore, neither the cleaning exercise nor the model scores establish behavior, prediction quality, or campaign impact for real mobile-game players.
